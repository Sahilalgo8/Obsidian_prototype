# Non-negotiable distinctions

From [[01 Executive recommendation]], section 1.3. These seven distinctions must be preserved in the graph model; collapsing any of them creates unsafe or ambiguous reasoning.

## Class versus instance

"Induction furnace" is a class; Furnace IF-204 is a physical instance. A model must never answer an instance question from class-level guidance without checking applicability.

## Process type versus execution

"Pouring" is a repeatable process type; Pour Event P-2026-08-05-441 is a time-bounded execution with material, equipment, operator and parameter context.

## Product definition versus physical product

Part 8472 Rev C is an information definition; Casting SN-99172 is the physical item produced to that definition.

## Observation versus state versus event

A temperature reading is an observation; "ladle temperature below window" is a state; a cold-shut occurrence is an event/imperfection.

## Imperfection versus defect versus nonconformance

An observed imperfection becomes a defect only when evaluated against requirements; a nonconformance is the governed failure to meet a requirement.

## Source claim versus approved knowledge

An email or chat creates a provenance-bearing assertion. It does not become operating guidance until reviewed, contextualized and approved.

## Recommendation versus decision versus action

The system proposes; an authorized role decides; the plant executes; the outcome is measured and fed back.
